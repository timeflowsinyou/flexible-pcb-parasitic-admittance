# Reproducibility protocol

## Input integrity

1. Copy original experimental files verbatim to `data/identification/` and `data/validation/` **only after sharing authorization**.
2. Record the exact acquisition files, measuring frequency, terminal-pair ordering, and loading metadata in `data/metadata/`.
3. Run `python scripts/create_sha256_manifest.py --write` after adding approved data. This creates a timestamped JSON audit file under `results/audits/` without modifying the input files.
4. To check a previous audit run `python scripts/create_sha256_manifest.py --verify results/audits/<manifest-name>.json`.
5. Keep processed data separately in `data/processed/`, generated by versioned standalone scripts. Do not silently patch source files.

## Analysis scripts (to be added)

- Joint identification of intrinsic unloaded baseline and shared 91 effective parasitic admittances from 644 states.
- Five-frequency unloaded recalibration using the independent unloaded sweep.
- Loaded-state fitting using known active sensing elements and complementary pair partitions.
- Full forward-model held-out predictions, including fixed parasitic admittances.
- Parasitic-free control comparison, with calibration differences explicitly documented.
- Manuscript figures/tables and per-run audit records.

## Environment (to be added)

Once final numerical scripts are identified, record the exact Python and numerical-library versions and a minimal environment specification. Do not claim an environment is reproducible until it has been tested in a clean installation.

## Validation integrity

The unloaded calibration uses all 91 unloaded terminal pairs. In loaded-state held-out evaluation, only loaded-state fitting pairs are excluded; this is *not* a completely unseen unloaded calibration. Compare raw measured impedance with the **full** forward prediction that includes fixed parasitics when reporting held-out Z errors. The compensated impedance should instead be compared with the *intrinsic* forward response for a separate consistency analysis.

## Release and confidentiality

Do not upload unreleased manuscript drafts, personal data, passwords, private paths, or original research data without coauthor/project permission. Initially keep the GitHub repository private; choose data/code public release terms and permanence before publication.
